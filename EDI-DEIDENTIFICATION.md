# 837 / 834 / 835 de-identification copy

Choose **View > De-identify EDI and Save Copy...** for a loaded 837I (`X223`), 837P (`X222`), 834 (`X220`), or 835 (`X221`) file. The viewer streams the original EDI file into a separate file in the source folder; it does not modify the original, the displayed temporary copy, or the current page. The copy is named `<source-base>_De-Identified_<yyyyMMddHHmmssfff><source-extension>` (for example `claim_De-Identified_20260102123456789.edi`). If the EDI was opened from a ZIP, the copy uses the extracted EDI entry's name and is placed beside the ZIP, not in the temporary extraction folder. Existing output files are never overwritten.

Edit `edi-deidentification.xml` beside `AnyText.exe` to change replacement values or add rules. The file is read each time you invoke the command; no restart is required. When it is missing, bundled defaults are used. Invalid configuration stops the operation rather than silently skipping rules. Edits to the project XML are copied to the output folder when the project is built; if you change the output copy directly, rebuilding can replace it.

Group rules under `<Transaction id="837" version="X223" name="837 Institutional">` for 837I, `<Transaction id="837" version="X222" name="837 Professional">` for 837P, `<Transaction id="834" version="X220" name="834 Enrollment">` for 834, and `<Transaction id="835" version="X221" name="835 Remittance">` for 835. Each parent has its own `<Replace ... />` children; the optional `name` is descriptive. Like EDI highlighting, the viewer detects `ST01` and the implementation version from `ST03` (or `GS08`), selects the matching transaction ID and version substring, and uses the longest matching version if multiple blocks apply. Only the selected parent's replacements run. A missing match, duplicate id/version, empty parent, or invalid rules stops the operation before writing the output. Existing custom XML with top-level `<Replace>` entries must be wrapped in Transaction parents; otherwise it is rejected instead of silently masking the wrong file.

A rule replaces the indicated 1-based element only when it is present and nonempty. For 837, `scope="Person"` applies in subscriber/patient (`HL03=22/23`) loops after an `NM1*IL` or `NM1*QC`; `scope="Claim"` applies anywhere within those loops (it is not a precise 2300 loop detector). For 834, `scope="Member"` starts at each `INS` and ends at the next `INS` or transaction end; `scope="MemberDetails"` starts at `NM1*IL` and ends at another `NM1`, `HD`, the next `INS`, or transaction end; `scope="Coverage"` starts at `HD` and ends at the next `NM1`, `INS`, or transaction end. `qualifierElement` and `qualifier` limit the rule to an exact element value. Optional `component` replaces only a 1-based component of the element, using the ISA component delimiter; otherwise the whole element is replaced.

For 835, `scope="ClaimPayment"` starts at `CLP` and applies to claim-level segments until the next `SVC`, `CLP`, or transaction end. `scope="ServicePayment"` starts at `SVC` and continues until the next `CLP` or transaction end; each new `SVC` begins another service. These are segment-based gates, not a full X12 loop parser. Default X221 rules replace CLP01 (patient account) and CLP07 (payer claim control), `NM1*QC` and `NM1*74` patient/corrected names (plus NM109 for `QC`), `REF*EA` account, claim dates `DTM*232`/`233`, service procedure `SVC01-2`, and service date `DTM*472`. They preserve other identifiers, payer/provider headers, payment amounts, adjustment codes and envelopes. Review additional qualifiers and identifiers before sharing.

Default 834 X220 rules replace member `REF*0F`/`REF*1L` identifiers, `NM1*IL` name and ID, member `PER` phone and email (`HP`/`EM`), `N3`/`N4` address, `DMG*D8` date of birth, and `DTP*348` coverage effective date after `HD`. File-header `REF`, `N1`, and other contact fields are not touched. These gates are deliberately simple; they do not parse all 834 loop variants. For 837 the existing defaults still include selected claim dates, diagnosis, SV2 (institutional) or SV1 (professional) procedure values.

This is a configurable *partial* de-identification aid, not a guarantee of HIPAA Safe Harbor or full anonymization. Review output for other identifiers (including free-text, other loops and qualifiers, provider data, and attachments) before sharing it. The output preserves EDI segment/element separators and original line breaks; replacement values must not contain the file's EDI delimiters. Files larger than memory are handled segment-by-segment, with a 1 MB per-segment limit. Failed runs delete the incomplete output copy.
