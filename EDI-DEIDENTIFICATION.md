# 837 de-identification copy

Choose **View > De-identify 837 and Save Copy...** for a loaded 837I (`X223`) or 837P (`X222`) file. The viewer streams the original EDI file into a separate file in the source folder; it does not modify the original, the displayed temporary copy, or the current page. The copy is named `<source-base>_Di-Identified_<yyyyMMddHHmmssfff><source-extension>` (for example `claim_Di-Identified_20260102123456789.edi`). If the EDI was opened from a ZIP, the copy uses the extracted EDI entry's name and is placed beside the ZIP, not in the temporary extraction folder. Existing output files are never overwritten.

Edit `edi-deidentification.xml` beside `AnyText.exe` to change replacement values or add rules. The file is read each time you invoke the command; no restart is required. When it is missing, bundled defaults are used. Invalid configuration stops the operation rather than silently skipping rules. Edits to the project XML are copied to the output folder when the project is built; if you change the output copy directly, rebuilding can replace it.

Group rules under `<Transaction id="837" version="X223" name="837 Institutional">` for 837I and `<Transaction id="837" version="X222" name="837 Professional">` for 837P. Each parent has its own `<Replace ... />` children; the optional `name` is descriptive. Like EDI highlighting, the viewer detects `ST01` and the implementation version from `ST03` (or `GS08`), selects the matching transaction ID and version substring, and uses the longest matching version if multiple blocks apply. Only the selected parent's replacements run. A missing match, duplicate id/version, empty parent, or invalid rules stops the operation before writing the output. Existing custom XML with top-level `<Replace>` entries must be wrapped in Transaction parents; otherwise it is rejected instead of silently masking the wrong file.

A rule replaces the indicated 1-based element only when it is present and nonempty. `scope="Person"` applies in subscriber/patient (`HL03=22/23`) loops after an `NM1*IL` or `NM1*QC`; `scope="Claim"` applies anywhere within those loops. `qualifierElement` and `qualifier` limit the rule to an exact element value. Optional `component` replaces only a 1-based component of the element, using the ISA component delimiter; otherwise the whole element is replaced. For example, the default `NM1*IL` rules replace subscriber name and ID; `N3`, `N4`, and `DMG` rules replace address and date of birth; selected `DTP`, `HI`, and `SV2` rules target the illustrated claim date, diagnosis and service values. Other transaction IDs or implementation versions are rejected.

This is a configurable *partial* de-identification aid, not a guarantee of HIPAA Safe Harbor or full anonymization. Review output for other identifiers (including free-text, other loops and qualifiers, provider data, and attachments) before sharing it. The output preserves EDI segment/element separators and original line breaks; replacement values must not contain the file's EDI delimiters. Files larger than memory are handled segment-by-segment, with a 1 MB per-segment limit. Failed runs delete the incomplete output copy.
